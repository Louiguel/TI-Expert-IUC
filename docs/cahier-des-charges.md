
# Cahier des charges — TI Expert IUC

## 1. Contexte

Le projet consiste à réaliser un site web de présentation du département
des Technologies de l'Information de l'Institut Universitaire de la Côte
à Douala.

## 2. Objectif général

Concevoir un site web clair, accessible et responsive permettant de
présenter les formations, les spécialités et les domaines d'expertise
associés au département TI.

## 3. Objectifs spécifiques

- Présenter le département.
- Décrire les cycles de formation communiqués pour le projet.
- Présenter les spécialités et domaines techniques.
- Mettre en valeur les atouts pédagogiques et techniques.
- Fournir un accès aux informations de contact.
- Développer le site avec HTML, CSS et JavaScript.
- Organiser le travail collaboratif avec Git et GitHub.
- Produire une documentation technique.

## 4. Besoins fonctionnels

BF01 — Afficher une page d'accueil.

BF02 — Présenter le département TI.

BF03 — Présenter le cycle court / collégial.

BF04 — Présenter le cycle Master TI-MASTER.

BF05 — Présenter les domaines d'expertise.

BF06 — Présenter les atouts annoncés du département.

BF07 — Permettre la navigation entre les sections.

BF08 — Afficher un menu adapté aux petits écrans.

BF09 — Proposer un accès au site officiel de l'IUC.

## 5. Besoins non fonctionnels

BNF01 — Responsive design : adaptation aux différentes tailles d'écran.

BNF02 — Accessibilité : structure sémantique, libellés et focus visibles.

BNF03 — Performance : limiter les dépendances externes et les ressources lourdes.

BNF04 — Maintenabilité : séparer le HTML, le CSS et le JavaScript.

BNF05 — Compatibilité : fonctionner sur les navigateurs modernes.

BNF06 — Versionnement : conserver l'historique des modifications avec Git.

BNF07 — Documentation : expliquer l'installation, l'organisation et les tests.

BNF08 — Fiabilité éditoriale : vérifier les informations institutionnelles avant publication.

## 6. Technologies

- HTML5
- CSS3
- JavaScript
- Git
- GitHub
- Visual Studio Code

## 7. Limites de la première version

Le site est statique. Il ne comporte ni base de données, ni authentification,
ni formulaire de contact connecté à un serveur.

## 8. Livrables

- Code source du site.
- Dépôt GitHub.
- Branches de travail.
- Documentation technique.
- Résultats des tests.
- Rapport final et captures d'écran.
